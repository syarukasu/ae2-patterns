# AE2 Patterns

<img src="shared/src/main/resources/assets/ae2mrp/textures/item/encoded_composite_pattern.png" alt="AE2 Patterns" width="128" height="128" align="right">

**AE2 Patterns** は、同じ完成品を作る複数の加工パターンをまとめ、
指定した生産割合でAE2の自動クラフト計画へ組み込むアドオンです。
素材不足時は「固定比率」か「自動再分配」を選べます。
元パターンは各機械のProviderに残したまま参照し、
エンコードした複合パターンをME接続ターミナルへ登録します。
実際の加工・搬入・搬出はAE2と元の機械が担当します。ACOの改造ではありません。

## 0.1.2

[GitHub Releases](https://github.com/syarukasu/ae2-patterns/releases) から、使用するMinecraftとLoaderに対応するJARを選んでください。
クライアントとサーバーの両方に、本MODとApplied Energistics 2が必要です。

- 空／エンコード済み複合パターン、薄型・壁付けの複合パターンターミナル1台。
- 元パターン8枠（4×2）、割合の直接入力・有効切替。
- エンコード、保存データの再編集、取り出せない編集プレビュー。
- AE2本体のパターンアクセス一覧・検索・スクロールを上段に配置。
- 中央に複合編集・登録、下段にAE2本体の通常エンコードを配置。一画面で同時表示。
- ワイヤレス複合パターンターミナル。AE2標準のリンク・電池・電波範囲を使い、登録先の設置端末を遠隔操作。
- 複合パターンの登録欄54枠。1行9枠をスクロール表示し、非表示の行も有効。編集中の比率ではなく、登録済みの設定だけがネットワークへ反映。
- 手置きした元パターンはエンコード成功後にプレイヤーへ返却。満杯なら端末の入力欄に保持。
- 2〜8種類、同じ主出力AEKey、割合合計100%、重複拒否。
- 固定比率（STRICT）／自動再分配（ADAPTIVE）を切替可能。
- 最大剰余法の同率は登録順、レシピ単位へ切り上げ。
- 自動再分配では不足分を他経路へ振り替え、成功したAE2仮在庫差分だけを共通在庫へ反映。
- AE2自身の在庫・不足・CPU bytes計算と通常CPU実行。
- Forge 1.20.1（AE2 15.4.10）／NeoForge 1.21.1（AE2 19.2.17）。
- 日本語・英語、添付画像2枚をアイテム素材として使用。

元パターンは消費しません。実行用の元パターンを各機械のPattern Providerへ入れ、
同じMEネットワークに接続した複合パターンターミナルの上段で選択します。
中央で割合とモードを指定してエンコードし、複合パターンを中央下の「登録」欄へ移します。
完成品のShiftクリックは一旦プレイヤーの在庫へ、在庫の複合パターンのShiftクリックは登録欄へ移動します。
従来のPattern Providerへの複合パターン登録も維持しています。
登録アイテムは専用の「AE2 Patterns」クリエイティブタブに表示されます。
アイテム画像は16×16pxです。保存データのMOD IDとレジストリIDは変更していません。

## ターミナルの使い方

### 検索と配分

上段はAE2本体のパターンアクセスターミナル画面です。
Provider別の表示、検索、縦スクロール、画面サイズ設定はAE2標準を使います。
パターンを左クリックすると参照登録し、出力名を検索欄へ入れます。元のProvider内の実物は動かしません。
検索の一致条件は導入済みAE2の仕様に従います。配分や登録のための画面切替はありません。
中央の「材料不足時」は「配分を守る」または「他のレシピで補う」から選びます。
前者は不足分を振り替えず、後者は登録済みの別レシピへ再配分します。

下段はAE2のエンコード用パネル・モードタブ・操作ボタン・通常パターンの処理を再利用します。
通常パターンの作成機能と、単純な加工パターンのみを受け付ける複合編集の対応範囲は別です。
設置端末の外観はAE2本体のフレーム・発光表示モデルを直接参照します。
AE2のモデルやテクスチャを本MODへ複製して配布するものではありません。

### ワイヤレス接続

1. AE2のワイヤレスターミナルと複合パターンターミナルをクラフトして作成します。
2. AE2標準の充電器で充電し、アクセスポイントのリンク用スロットで同じネットワークへリンクします。
3. 操作したい設置型の複合パターンターミナルを、スニークしながらワイヤレス端末で右クリックして登録します。
4. 手に持って右クリックします。メインハンド、オフハンド、インベントリからのAE2標準起動に対応します。

複合パターンは設置端末に保存されます。複数のプレイヤーでも同じ登録欄を操作し、
ワイヤレスを閉じたり電池が切れたりしても登録内容は消えません。
範囲外、リンク解除、別ネットワーク、設置端末の削除・アンロード、手持ちアイテムの変更では操作を拒否します。
チャンクを強制ロードせず、範囲無制限化や独自の無消費電力経路は追加しません。
Curios等の外部スロットは今回の対象外です。

## レシピ対応範囲

作業台パターン（加工パターンとの混在を含む）、入れ子、代替入力、返却容器、複数出力や動的パターン、
独自の物理クラフト実行は含みません。BigIntegerで分配計算しますが、
既定のAE2接続はlong範囲のみです。範囲外は明示失敗し、丸めません。
自動再分配は指定割合を先に満たす方式で、全配分の組合せを探索する最適化ソルバーではありません。

## 計算経路の選択

サーバー側に生成される `ae2mrp-server.toml` で設定します。既定はAE2です。
Forgeでは通常ワールドの `serverconfig` 内です。

```toml
plannerBackend = "AE2"
```

対応するACOのNative VMを導入している場合は `"ACO"` に変更できます。
サーバー側で選択し、STRICT／ADAPTIVEの両方へ適用します。変更は新しい注文へ
適用され、既存ジョブや保存済みパターンの割合は変更しません。

- AE2: これまでのネイティブ計算・分配経路。
- ACO: ACOのVM・在庫Snapshot・BigInteger演算・結果生成を利用。
  分配制御は本MODが接続し、元パターンだけを実行計画に残します。
- ACO未導入・非対応のVM構造は明示エラー。勝手に別経路へ切り替えません。
- 確認対象はVM `0.3.12-vm-refs.8` とNeoForge版の同系統です。
  ACOの全過去版・将来版との互換性を意味しません。
- ACO経路のwide数量はACOの正確数量契約と消費側に委ねます。
  今回の試験はlong範囲の計画比較・通常CPU完走であり、巨大注文の実環境完走は未検証です。

複合パターンを使わない注文について、サーバー全体のACO設定を上書きしません。

JDK 17 / 21を用意し、`gradlew :forge:build :neoforge:build` を実行します。
配布用JAR・チェックサム・変更履歴は [Releases](https://github.com/syarukasu/ae2-patterns/releases) に掲載します。
